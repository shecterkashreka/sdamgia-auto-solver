# УЛЬТИМАТИВНЫЙ ГАЙД ПО АВТОМАТИЗАЦИИ И РЕШЕНИЮ ТЕСТОВ СДАМ ГИА (РЕШУ ЕГЭ / ОГЭ / ВПР) ДЛЯ AI-АССИСТЕНТА

Ты — автономный AI-ассистент, управляющий полным циклом: «Установка окружения -> Авторизация -> Выгрузка варианта -> Решение -> Сверка -> Заполнение -> Скриншот до отправки -> Отправка -> Скриншот результата».

### Структура папок проекта:
- `screenshots/` — скриншоты эмулятора:
  - `before_submission.png` — полный скриншот страницы с заполненными полями ДО отправки.
  - `submission_result.png` (`after_submission.png`) — скриншот подтверждения отправки ПОСЛЕ вызова `submit_form()`.
- `cache/` — промежуточные файлы парсинга, дампы HTML (`live_test_page.html`), отладочные фрагменты DOM и временные тексты.
- `scripts/` — вспомогательные скрипты, модули решения задач (математические верификаторы, скрипты динамического программирования, парсеры и алгоритмы).
- `files/` — скачанные с платформы вложения и графические материалы заданий (`/get_file?id=...`).
- `run_session.py` — главный исполняемый скрипт сессии.
- `answers.json`, `tasks.json`, `tasks.txt` — ключевые файлы данных текущего варианта.

## 0. ПЕРВИЧНАЯ УСТАНОВКА И ПРОВЕРКА ОКРУЖЕНИЯ (ДЛЯ НЕЙРОСЕТИ)

Если ты запускаешься на новой машине или в свежем терминале, сначала выполни проверку и установку зависимостей:

1. **Проверка Python:** требуется Python версии 3.10 или выше.
2. **Установка необходимых библиотек:**
   ```bash
   pip install -r requirements.txt
   ```
   *(Библиотеки: `playwright`, `beautifulsoup4`)*
3. **Установка браузера Playwright (Microsoft Edge / Chromium):**
   ```bash
   playwright install msedge
   ```
   *(Если в системе уже установлен Microsoft Edge, Playwright сможет использовать системный дистрибутив `channel="msedge"`)*.

## 1. АРХИТЕКТУРА ПЛАТФОРМЫ И ПОДВОДНЫЕ КАМНИ (ОБЯЗАТЕЛЬНО К ПРОЧТЕНИЮ)

1. **Индивидуальные варианты от учителя (параметры `continue` и `rtid`):**
   - Если учитель выдал индивидуальный вариант, при входе в тест появляется модальное окно: `«Вы уже начинали решать этот вариант: [Продолжить решение] / [Начать заново]»`.
   - **КРИТИЧЕСКИ ВАЖНО:** Кликать ТОЛЬКО `«Продолжить решение»` (`a:has-text("Продолжить решение")` или `a[href*="continue="]`). Клик «Начать заново» сгенерирует ДРУГОЙ вариант с новыми заданиями, и подготовленные ответы не подойдут!
2. **Сессионные токены (Куки):**
   - Авторизация хранится в файле `cookies.json`. Ключевые токены: `atoken` и `rtoken` (домен `.sdamgia.ru`).
   - Если сайт редиректит на форму логина или пишет «необходимо авторизоваться», пользователю нужно обновить значения `atoken` и `rtoken` в `cookies.json`.
3. **Структура заданий в DOM:**
   - Каждый контейнер задачи имеет тег: `<div class="prob_maindiv" data-num="X" data-id="Y">`, где `data-num` — порядковый номер в тесте, `data-id` — уникальный постоянный ID задачи в каталоге платформы.
   - Имена полей ввода строятся по схеме:
     - Одиночные поля: `answer_{data-num}_{data-id}`
     - Составные поля (2 ответа, таблицы, координаты): `answer_{data-num}_{data-id}_{подномер}` (например, `_1`, `_2`).
     - Развёрнутые ответы: `textarea` или `input` с соответствующим `name`.
4. **Механизм отправки формы:**
   - На платформе вызов JavaScript-функции `page.evaluate("submit_form()")` собирает все элементы класса `.test_inp`, клонирует их в скрытую форму и делает POST-запрос на `/test`.

## 2. ПРАВИЛА ОФОРМЛЕНИЯ РАЗВЁРНУТЫХ ОТВЕТОВ

### ПРАВИЛО 1. СТРОГИЙ ЗАПРЕТ НА ПРИКРЕПЛЕНИЕ ФАЙЛОВ И КАРТИНОК
> **СТРОГО ЗАПРЕЩЕНО:** Нейросети категорически запрещается загружать или прикреплять файлы, скриншоты, графики или изображения в форму ответа (даже если интерфейс сайта это позволяет). 
> Все ответы передаются **ИСКЛЮЧИТЕЛЬНО в виде обычного текста** в поля ввода!

### ПРАВИЛО 2. МАКСИМАЛЬНАЯ КРАТКОСТЬ (ЧЕМ КОРОЧЕ — ТЕМ ЛУЧШЕ)
> Не пиши «сочинений» там, где требуется решение.
> Никакой лишней воды, длинных вступлений, шаблонных фраз искусственного интеллекта («Давайте подробно рассмотрим...», «Как языковая модель...»).
> Решение должно быть максимально лаконичным, плотным и по делу:
> - Дано / ОДЗ (если есть).
> - 2–4 строчки ключевых математических/логических преобразований.
> - Итоговый ответ.
> Длина ответа должна быть ровно такой, чтобы эксперту было достаточно для максимального балла, но без единого лишнего слова.

### ПРАВИЛО 3. «ЧЕЛОВЕЧНЫЙ ВИД» БЕЗ МАШИННОГО СИНТАКСИСА И БЕЗ LATEX
> **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ:** Никакого сырого LaTeX-кода или синтаксиса программирования!
> Запрещено: `\sqrt{10}`, `\frac{a}{b}`, `sqrt(10)`, `\pm\infty`, `**2`, `^2`, `===`, `&&`, `||`.
> Текст должен выглядеть так, как будто ученик набрал его вручную с телефона или простой клавиатуры.

| Машинный вид (ЗАПРЕЩЕНО) | Человечный вид (ПРАВИЛЬНО) | Пример использования |
|---|---|---|
| `\sqrt{10}` или `sqrt(10)` | `корень из 10` или `√10` | `x = 2 + √10` или `x = 2 + корень из 10` |
| `\pm\infty` | `+-бесконечность` или `±бесконечность` | `(-бесконечность; 5]` |
| `x^2`, `x**2` | `x²` (маленькая 2) или `x^2` | `x² - 5x + 6 = 0` |
| `x^3`, `x**3` | `x³` (маленькая 3) | `2x³ + 4` |
| `\frac{3}{4}` | `3/4` | `x = 3/4` |
| `\le`, `\ge`, `>=` | `<=`, `>=` или `≤`, `≥` | `x >= -3` |
| `\ne`, `!=` | `!=` или `не равно` | `ОДЗ: x != 3` |
| `\pi` | `пи` или `π` | `x = пи/4 + пи*k, k целое` |
| `\cdot`, `*` | `*` или `·` | `2 * 3 = 6` |
| `\in` | `принадлежит` или `∈` | `x принадлежит [-2; 7)` |
| `\cup` | `объединение` или `знак U` | `(-бесконечность; 0) U (0; +бесконечность)` |
| `--` (двойной дефис) | `-` (одинарный дефис) или `—` (тире) | `точка K - середина` |

### ПРАВИЛО 4. ПУНКТУАЦИЯ: СТРОГО ОДИНАРНЫЙ ДЕФИС/ТИРЕ (`-`, А НЕ `--`)
> **СТРОГО ЗАПРЕЩЕНО:** Использовать двойные дефисы `--` вместо тире!
> Пиши **строго один дефис `-`** (с пробелами по бокам) или типографское тире `—`.
> - **Запрещено:** `AC1 -- проекция`, `точка K -- середина`, `треугольник -- равнобедренный`.
> - **Правильно:** `AC1 - проекция`, `точка K - середина`, `треугольник - равнобедренный`.

**Пример идеального краткого развёрнутого ответа:**
```text
ОДЗ: x > 0, x != 1.
Преобразуем: log2(x) = t => t² - 3t + 2 = 0.
Корни: t1 = 1, t2 = 2.
Обратная замена: x = 2 или x = 4. Оба входят в ОДЗ.
Ответ: 2; 4
```

## 3. СТАНДАРТНЫЙ ПОЛНЫЙ ЦИКЛ РАБОТЫ (WORKFLOW)

### ЭТАП 1. Выгрузка актуального варианта и файлов (Trial Run)
Запусти скрипт в режиме предварительной сверки (без отправки):
```powershell
python -u run_session.py --url "ССЫЛКА_НА_ТЕСТ" --trial
```
Скрипт:
1. Запустит браузер в видимом режиме с куками из `cookies.json`.
2. Нажмет «Продолжить решение» при наличии окна с вариантом.
3. Извлечет все задания и сохранит в `tasks.json` и `tasks.txt`.
4. Скачает все вложения (`/get_file?id=...`) в локальную папку `files/`.

---

### ЭТАП 2. Решение заданий любого типа

1. **Краткие ответы (Часть 1):** строго по правилам формата (число, слово без пробелов, последовательность цифр).
2. **Развёрнутые ответы (Часть 2):** текст строго по правилам Раздела 2 (максимальная краткость, без файлов/картинок, человечный вид корней и степеней).
3. **Вычисления и код:** используй Python для любых расчётов, обработки таблиц (.ods/.xlsx) и текстовых файлов.

---

### ЭТАП 3. Формирование файла `answers.json`

Файл `answers.json` создаётся в текущей папке бота:

```json
{
  "1": "26",
  "2": "xwzy",
  "12": "cos(2x) = 0\n2x = пи/2 + пи*k\nx = пи/4 + (пи*k)/2, k целое.\nОтвет: пи/4 + (пи*k)/2",
  "17": ["3", "44335"],
  "25": ["1072461", "1272460371", "1772469231"]

```

### ЭТАП 4. Защитная предпроверка (Variant Verification)

Перед отправкой скрипт ОБЯЗАН сверить DOM открытой страницы с выгруженным `tasks.json`:
```python
def verify_variant_match(page, expected_tasks):
    live_tasks = page.eval_on_selector_all(
        ".prob_maindiv",
        "elements => elements.map(el => ({num: el.getAttribute('data-num'), id: el.getAttribute('data-id')}))"
    )
    # Сравнивает каждый data-id. Если есть хоть одно несовпадение -> БЛОКИРОВКА ОТПРАВКИ!
```

---

### ЭТАП 5. Заполнение, скриншот ДО отправки, случайная задержка (накрутка времени) и отправка

Запуск боевого скрипта:
```powershell
python -u run_session.py --url "ССЫЛКА_НА_ТЕСТ" --test-dir "tests/ID_ТЕСТА" --auto-submit --delay 20-40
```
Скрипт:
1. Загружает страницу в той же сессии.
2. Проверяет совпадение всех заданий по `data-id`.
3. Заполняет все инпуты и текстовые поля на основе `answers.json`, подсвечивая заполненные поля зелёной рамкой.
4. **Скриншот ДО отправки:** делает полный снимок всей страницы с введёнными ответами и сохраняет в `tests/<id>/screenshots/before_submission.png`.
5. **Накрутка времени решения (случайная задержка 20–40 минут):** браузер остаётся открытым на странице теста заданное случайное время (имитация живого решения учеником для фиксации таймера на платформе). В консоль выводится обратный отсчёт.
6. По истечении таймера вызывает `page.evaluate("submit_form()")`.
7. Дожидается завершения запроса и сохраняет скриншот подтверждения отправки в `tests/<id>/screenshots/submission_result.png`.

## 4. МНОГОЗАДАЧНОСТЬ И ПАКЕТНЫЙ ЗАПУСК НЕСКОЛЬКИХ ДЗ (MULTITASKING)

Если пользователь передал сразу несколько ссылок на тесты, например:
`https://math-ege.sdamgia.ru/test?id=92423661 https://inf-ege.sdamgia.ru/test?id=20866705 "AI_GUIDE.md"`

ИИ действует по принципу неблокирующей многозадачности:

1. **Изоляция окружения:**
   Каждое ДЗ обрабатывается в отдельной папке: `tests/<ID_1>/`, `tests/<ID_2>/` и т.д.
2. **Параллельная/последовательная выгрузка:**
   Запускается пробный сбор вариантов:
   ```powershell
   python batch_runner.py ССЫЛКА_1 ССЫЛКА_2 --trial
   ```
3. **Конвейер решения и независимых таймеров:**
   - ИИ решает **Тест 1** -> сохраняет `tests/<ID_1>/answers.json`.
   - ИИ запускает отправку Теста 1 в **фоновом режиме** с таймером 20–40 мин:
     ```powershell
     python -u run_session.py --url ССЫЛКА_1 --test-dir tests/<ID_1> --auto-submit --delay 20-40
     ```
   - **НЕ ДОЖИДАЯСЬ** истечения 20–40 минут Теста 1, ИИ **СРАЗУ** переходит к решению **Теста 2**!
   - ИИ решает **Тест 2** -> сохраняет `tests/<ID_2>/answers.json`.
   - ИИ запускает отправку Теста 2 в фоновом режиме со своим собственным случайным таймером (20–40 мин):
     ```powershell
     python -u run_session.py --url ССЫЛКА_2 --test-dir tests/<ID_2> --auto-submit --delay 20-40
     ```
   - У каждого теста активен свой независимый таймер накрутки часов, отдельный браузерный процесс и собственные скриншоты в `tests/<ID>/screenshots/`.
